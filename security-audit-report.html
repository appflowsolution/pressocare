🧩 DETALLES:

1. Credenciales y Secretos (CRÍTICO)

Archivo: js/app.js (Líneas 21-28)

Problema: El objeto firebaseConfig expone la clave apiKey y otros identificadores de Firebase directamente en el código del cliente frontend.

Recomendación: Aunque en Firebase es estándar exponer el `apiKey` en el cliente web, debes asegurarte de ir a Google Cloud Console y restringir la API Key **únicamente** a los dominios autorizados de tu aplicación (ej. tu dominio en producción y localhost). Considera extraer la configuración a variables de entorno en frameworks modernos.

2. Base de Datos Firebase (Seguridad) (MEDIO)

Archivo: Raíz del proyecto

Problema: No se ha detectado ningún archivo con las reglas de seguridad locales (ej. firestore.rules). Las reglas no están bajo control de versiones.

Recomendación: Define y audita un archivo `firestore.rules` en el repositorio que verifique que el usuario autenticado solo pueda leer y escribir datos propios (request.auth.uid == userId).

3. Arquitectura (MEDIO)

Archivo: js/app.js

Problema: Toda la lógica de la aplicación y operaciones CRUD se ejecutan desde el código del cliente.

Recomendación: Para un tracker real o entorno HIPAA, la lógica sensible o validaciones de la creación de perfiles debería realizarse mediante Cloud Functions en el backend.

4. Dependencias Externas (OK)

Archivo: index.html

Problema: Carga de scripts desde CDNs públicos (Tailwind, Chart.js, Firebase).

Recomendación: Usar Subresource Integrity (SRI) en las dependencias cargadas desde CDNs añadiendo `integrity` y `crossorigin` hashes para mayor prevención contra ataques Supply Chain.
