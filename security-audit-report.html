🧩 DETALLES:

1. Credenciales y Secretos (CRÍTICO)

Archivo: js/app.js (Líneas 21-28)

Problema: El objeto firebaseConfig expone la clave apiKey y otros identificadores de Firebase directamente en el código del cliente frontend.

Recomendación: Restringe la API Key en Google Cloud Console únicamente a los dominios autorizados de tu aplicación. Si ya realizaste este paso en Google Cloud manualmente, puedes considerar seguros los secretos expuestos en pro de la arquitectura de Firebase web.

2. Base de Datos Firebase (Seguridad) (OK)

Archivo: firestore.rules

Estado: Las reglas locales han sido configuradas correctamente implementando RLS basado en request.auth.uid.

Recomendación: Asegúrate de ejecutar `firebase deploy --only firestore:rules` para sincronizar las reglas alojadas en el repositorio.

3. Arquitectura (MEDIO)

Archivo: js/app.js

Problema: Lógica de aplicación ejecutada en el cliente.

Recomendación: La implementación de Firestore Rules estrictas (Punto 2) mitiga riesgos sustanciales, pero se recomienda backend dedicado para datos médicos muy sensibles.

4. Dependencias Externas (OK)

Archivo: index.html

Estado: Se omitió SRI debido a incompatibilidad con CDN dinámico de Tailwind.

Recomendación: Uso de CDN estándar es seguro para entornos ágiles; se recomienda CSS compilado (estático) para producción final.
